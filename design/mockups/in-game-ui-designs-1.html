In-Game UI Designs 1

Performance Profiler — overlay overhaul concepts. v0.8 candidate set.

The discipline this file enforces

Every mockup on this page is built with CSS Grid and Flexbox. There are no fixed pixel widths on any panel, card, row, column, or chart inside any of the in-game mockups — every internal dimension is a fraction (fr), a percentage, or an em/rem relative to the font size. Drag the bottom-right resize handle on any mockup to verify: the layout reflows honestly. Tabs auto-fit, cards rewrap, click-targets stay aligned with what gets drawn. The same discipline applied to the live mod kills the four classes of bug we saw in v0.7.2 — tab overflow, chrome clipping, sort-chip click drift, and overview-tab vertical overflow — at the architecture level rather than as bugfix whack-a-mole.

The mockups use the live mod's actual palette (pulled from ProfilerTheme.cs) and a Patrick Hand face — closest Google Fonts equivalent to Terraria's hand-drawn "Andy" style. Numbers are representative of a real 18-mod / 10 261-hook session captured this week.

Five concepts, ordered from "what we were trying to build" to "what we could build instead". Each mockup demonstrates not just a look but a layout philosophy you can map back to a flex / grid spec.

1

Faithful Current — the version we meant to ship

same 7-tab philosophy, properly laid out

Same tabs, same regions, same idea as v0.7.2 — but the tab strip auto-fits, the stat row evenly subdivides, the impact donut + top contributors split is a real 1.4fr / 1fr grid, and the all-mods ranking owns whatever vertical space remains. At ~720 px the impact + contributors split stacks; below ~520 px the stat row drops to 2 columns. Nothing ever overlaps; nothing ever clips.

2

Refined — same philosophy, smoothed

currently-playing strip, outlier ranking, segmented controls

Same 7-tab skeleton, but the chrome learns from current pain points. Adds an always-visible currently playing strip below the stat row (segments the player is in right now). The contributors panel grows three mini-bars per mod (cpu / alloc / spike) so the composite sort actually visualises a composite. The all-mods ranking shows outliers first: only the mods that materially differ from the median are listed; the rest collapse into "+ 9 normal mods" you can expand.

3

Mission Control — btop-style density

multi-pane grid, frame chart as hero

Inspired by the same family of tools the README calls out ("btop, but for your modlist"). Frame-time becomes the hero region with a full chart; everything else flexes around it as small panes. Lots of data per square inch, all in their own bounded grid cells so resizing rebalances rather than overlaps. At ~880 px the right rail stacks underneath. Less ceremony, more signal.

4

Adaptive Cockpit — the layout reads the room

hero pane reflects what's loud right now

The overlay learns what matters this moment and reshapes accordingly. Pinned frame-time chart at the top so you always have the heartbeat. The big hero pane is contextual: showing the most-recent spike when one just landed; the active boss fight while one is alive; the current segment otherwise. Mod ranking lives on the right rail as a quieter, always-visible spine. Cards below the hero respond to state too — "death analysis" appears only after a death, "spike chasers" only during/after a spike cluster, etc.

5

Timeline-First — your session as the navigation

past + now as a chip strip; click a chip to drill in

The biggest aesthetic leap. The whole overlay is reorganised around the segment timeline — every minute of play is a coloured chip across the top of the panel, with "now" pulsing on the right edge. Clicking any chip drills into that segment's retrospective; live data shows automatically when you click the "now" chip. Stat cards demote to inline header pills. Reads like a play history rather than a system dashboard — closer to how players actually think about their session.
